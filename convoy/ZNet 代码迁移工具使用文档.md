# ZNet 代码迁移工具使用文档

本工具集提供两个命令行程序，用于自动将 **ZNet** 或 **ZNetV2** 项目的 Pascal 源码迁移到不同目标版本。所有转换基于词法分析，比正则替换更精准可靠。

---

## 一、工具概述

| 工具名称 | 可执行文件 | 迁移方向 | 适用场景 |
|---------|-----------|---------|----------|
| **ZNet → ZNetV2 升级工具** | `update_znet_to_znetv2` | 旧版 ZNet → 新版 ZNetV2（主库） | 将基于旧版框架的项目升级到最新主库 |
| **ZNetV2 主库 → 副库迁移工具** | `update_znetv2_to_sec` | ZNetV2 主库 → ZNetV2 副库（`sec/`） | 将使用主库的项目转为轻量副库版本 |

> **副库（`source/sec/`）** 是主库的精简分支，剔除了部分高级特性，但保留了核心网络和基础功能。其最大优势是支持 **双主线程（Dual-Main-Thread）技术**，使迁移后的副库程序能够将原有 ZNetV2 的网络服务**完全静默运行于后台线程**，**100% 不占用主线程**，从而让主线程专注于 UI 渲染或业务逻辑，显著提升用户体验。

---

## 二、编译指南（使用 lazbuild）

本工具使用 **Lazarus / Free Pascal** 开发，编译最简单的方式是使用 Lazarus 自带的命令行构建工具 **lazbuild**。

### 2.1 准备工作

- 确保已安装 **Lazarus**（建议 2.0+），并确认 `lazbuild` 可执行文件已加入系统 `PATH`，或能通过完整路径调用。
- 确保项目源码目录结构完整，特别是 `source/` 目录下的所有 `.pas` 和 `.inc` 文件必须存在。
- 两个工具的 Lazarus 项目文件位于 `convoy/` 目录下：
  - `update_znet_to_znetv2.lpi`
  - `update_znetv2_to_sec.lpi`

### 2.2 编译步骤

打开终端（cmd / PowerShell / bash），切换到 `convoy` 目录，执行以下命令：

#### 编译第一个工具（ZNet → ZNetV2）
```bash
lazbuild -B "update_znet_to_znetv2.lpi"
```

#### 编译第二个工具（主库 → 副库）
```bash
lazbuild -B "update_znetv2_to_sec.lpi"
```

### 2.3 常用编译选项

| 选项 | 作用 |
|------|------|
| `-B` 或 `--build-all` | 强制重新编译所有文件（建议每次使用，避免依赖缓存问题） |
| `--build-mode=<模式>` | 指定构建模式，如 `Release` 或 `Debug`（若不指定，默认使用项目中的活动模式） |
| `--cpu=<目标CPU>` | 指定目标 CPU，如 `i386`、`x86_64` |
| `--os=<目标OS>` | 指定目标操作系统，如 `win32`、`linux`、`darwin` |

#### 示例（指定发布模式并编译 64 位 Windows 版）
```bash
lazbuild --build-mode=Release --cpu=x86_64 --os=win32 -B "update_znet_to_znetv2.lpi"
```

### 2.4 编译结果

编译成功后，可执行文件将输出到 Lazarus 项目设置中指定的目录（通常是 `convoy\` 下的 `bin\` 或 `lib\` 子目录，具体取决于您的 LazBuild 配置）。您也可以直接通过 `lazbuild` 的输出信息查看生成路径。

## 三、使用方法

两个工具的命令行用法完全相同，仅可执行文件名不同。

### 3.1 基本语法
```bash
<工具名>.exe "目标项目目录路径"
```

### 3.2 示例
```bash
# Windows
update_znet_to_znetv2.exe "C:\MyProjects\OldZNetApp"
update_znetv2_to_sec.exe "D:\Work\ZNetV2_Project"

# Linux / macOS
./update_znet_to_znetv2 "/home/user/projects/myapp"
./update_znetv2_to_sec "/home/user/projects/lightweight"
```

### 3.3 支持的文件类型
工具会递归扫描指定目录下的以下扩展名文件：
- `.pas` – Pascal 单元
- `.dpr` – Delphi 项目
- `.lpr` – Lazarus 项目
- `.pp` – Free Pascal 源文件
- `.inc` – 包含文件

所有匹配的文件都会被就地修改（**直接覆盖**）。

### 3.4 执行过程
- 工具启动后，会显示目标目录路径。
- 加载内嵌的迁移模型（模型规则已编译进可执行文件，无需外部数据文件）。
- 依次遍历每个文件，根据模型规则执行标识符重命名、单元引用替换、`uses` 子句更新、编译器指令中的文件名修正等操作。
- 每处理一个文件都会输出详细日志，便于追踪修改内容。
- 完成后提示检查代码并重新编译。

## 四、迁移模型说明

转换规则内置于 `ZNet_To_ZNetV2_Model` 单元中，以预编译二进制数据的形式打包进可执行文件，无需外部配置文件。若需定制迁移规则，可联系作者或通过修改该单元重新编译工具（修改模型数据需要对应的生成工具，一般用户无需操作）。

---

## 五、副库双主线程技术优势

使用 `update_znetv2_to_sec` 将项目迁移到副库后，您可以获得以下关键能力：

- **服务后台化**：原有的 ZNetV2 网络服务（如 C4 通信、文件传输、数据库连接等）可以完全运行在独立的后台线程中，**与主线程彻底分离**。
- **主线程零占用**：通过双主线程架构，后台服务不会阻塞 UI 刷新、动画渲染或任何主循环逻辑，实现 **100% 主线程空闲**。
- **提升响应性**：对于图形界面应用（如游戏、工具软件），这种设计能保证界面始终保持流畅，即使网络负载很高也不会卡顿。
- **极简改造**：迁移工具自动处理单元引用和 API 适配，您只需在迁移后按副库文档启用双主线程模式即可，无需重写业务逻辑。

这意味着，您可以将原本臃肿的同步服务转变为轻量、异步的后台守护程序，非常适合嵌入式、移动端或桌面应用场景。

## 六、注意事项（重要！）

- **⚠️ 备份原项目！** 工具会 **直接修改** 源文件，无法撤销。请务必在运行前对整个项目目录进行完整备份。
- 建议先在 **测试副本** 上运行，确认迁移效果后再应用于正式代码。
- 工具依赖 `Z.Core`、`Z.PascalStrings` 等基础库，编译时必须确保 `source/` 目录在搜索路径中（项目文件已配置，一般无需额外设置）。
- 迁移完成后，请仔细检查代码差异，使用目标框架重新编译并运行测试套件，确保业务逻辑无误。
- 若遇到模型加载失败（退出码 2），请检查可执行文件是否完整，或重新编译。

---

## 七、错误码速查

| 退出码 | 含义 |
| :---: | :--- |
| 0 | 执行成功，所有文件处理完毕 |
| 1 | 指定的目标目录不存在或无法访问 |
| 2 | 模型数据加载失败（可执行文件可能损坏） |
